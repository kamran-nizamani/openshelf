# OpenShelf Supabase setup guide

This guide prepares a Supabase project for OpenShelf. The repository includes a starter database schema, row-level security (RLS) policies, and two Storage buckets. **The app screens are not connected to Supabase yet**: book listings still use sample data, and the login, registration, upload, and report forms are previews. Setting up Supabase does not make those screens live by itself.

## 1. Create a Supabase project

1. Sign in at [supabase.com](https://supabase.com/) and create an organization if needed.
2. Select **New project**.
3. Give it a name, choose a strong database password, and select a region close to your users.
4. Save the database password in a password manager. It is not the same as an API key.
5. Wait until the project status is ready.

For an existing project with data, do not run the starter schema blindly. Review it and create a migration for the existing database first.

## 2. Create the database tables and policies

1. Open the project dashboard and select **SQL Editor**.
2. Open `supabase/schema.sql` in this repository and copy its complete contents.
3. Create a new SQL query, paste the contents, and select **Run**.
4. Confirm the query completes without an error.

The script creates the profile, category, book, saved-book, review, report, and moderation tables; enables RLS; installs a profile-creation trigger; adds starter categories; and creates:

- `book-covers`: public images, limited to 5 MB and JPG, PNG, or WebP.
- `book-files`: private PDFs, limited to 20 MB.

PDF object paths are expected to start with the owner's user ID, for example `<auth-user-uuid>/<random-name>.pdf`. Cover paths use the same folder convention. The policies allow users to upload only into their own folders. Approved PDF access is intended to use a signed URL generated by a trusted server after the app integration is implemented.

The SQL is repeatable on a fresh project, but it is a **starter schema**, not a migration tool. `CREATE TABLE IF NOT EXISTS` will not update an older table's columns or constraints.

## 3. Check that the schema was created

In SQL Editor, run:

```sql
select table_name
from information_schema.tables
where table_schema = 'public'
order by table_name;
```

You should see tables including `profiles`, `categories`, `books`, `saved_books`, `reviews`, `reports`, and `user_roles`.

Check RLS is enabled:

```sql
select tablename, rowsecurity
from pg_tables
where schemaname = 'public'
order by tablename;
```

Check categories and buckets:

```sql
select name from public.categories order by name;

select id, name, public, file_size_limit
from storage.buckets
where id in ('book-covers', 'book-files')
order by id;
```

The `book-covers` bucket should be public; `book-files` should be private.

## 4. Configure email authentication

1. In the Supabase dashboard, open **Authentication → Providers → Email**.
2. Enable email/password sign-in.
3. Decide whether email confirmation should be required. It is recommended for a public service. Configure SMTP before launch if you need reliable production delivery; default email service limits may apply.
4. Open **Authentication → URL Configuration**.
5. Set the **Site URL** to `http://localhost:3000` for local development.
6. Add `http://localhost:3000/**` to the allowed redirect URLs.
7. When deploying, add your exact production URL and callback/redirect URLs too. Do not leave a production project pointing only at localhost.

The profile trigger in `schema.sql` creates a `public.profiles` row when a new Supabase Auth user is created. It copies the user's `full_name` metadata and email.

## 5. Add the public project settings locally

1. From the project folder in PowerShell, create `.env.local`:

   ```powershell
   Copy-Item .env.example .env.local
   ```

2. In Supabase, open **Project Settings → API** (or **API Keys**, depending on the dashboard version).
3. Copy the project URL and the **publishable** key, or the legacy **anon** key.
4. Open `.env.local` and set:

   ```dotenv
   NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY
   NEXT_PUBLIC_SITE_URL=http://localhost:3000
   ```

   The existing client helper reads `NEXT_PUBLIC_SUPABASE_ANON_KEY`; a publishable key can be used as its value.

5. Save the file and restart the Next.js development server after changing environment variables.

The anon/publishable key is intended for browser use and is safe to expose **only when RLS is enabled and correctly configured**. Never put a `service_role` or secret key in this file, in a `NEXT_PUBLIC_*` variable, or in browser code. `.env.local` is ignored by Git.

## 6. Start the app and understand the current state

Run:

```powershell
npm run dev
```

Visit `http://localhost:3000`. The app should still show the sample catalogue and preview messages. That is expected: the current book routes, account forms, and upload form have not yet been wired to Supabase.

## 7. Verify Auth profile creation

Until the app's sign-up form is integrated, use a temporary test user:

1. In Supabase, open **Authentication → Users** and create a test user with an email and password.
2. In SQL Editor, check that the profile trigger ran:

   ```sql
   select id, full_name, email, created_at
   from public.profiles
   order by created_at desc
   limit 5;
   ```

3. Delete the test account from **Authentication → Users** when finished. Its profile is set to cascade-delete with the Auth user.

Do not use a real user's password for this test.

## 8. Grant admin access carefully

Do not add an admin role through a public sign-up form. First create your own account, then use the SQL Editor (which runs with elevated database permissions) to grant the role to that exact account:

```sql
insert into public.user_roles (user_id, role)
select id, 'admin'
from auth.users
where email = 'YOUR_VERIFIED_ACCOUNT_EMAIL'
on conflict (user_id, role) do nothing;
```

Verify the role:

```sql
select u.email, r.role
from auth.users as u
join public.user_roles as r on r.user_id = u.id
where u.email = 'YOUR_VERIFIED_ACCOUNT_EMAIL';
```

Only grant this to a trusted account. The frontend admin page is currently a preview and does not implement admin authentication or moderation actions.

## 9. Configure deployment

When deploying (for example, on Vercel):

1. Add `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, and `NEXT_PUBLIC_SITE_URL` in the hosting provider's environment settings for the correct environments.
2. Add the production domain and any auth callback URLs in Supabase **Authentication → URL Configuration**.
3. Redeploy after setting or changing environment variables.
4. Keep database backups enabled and configure production email delivery.
5. Review the RLS policies and storage rules before accepting real user data or copyrighted content.

## 10. What remains before the app uses the database

Supabase provisioning is only the foundation. The next app-integration work is:

1. Connect registration, login, logout, and password reset to Supabase Auth.
2. Replace sample book queries with approved rows from `public.books`.
3. Upload covers and PDFs to the two Storage buckets, then insert pending book metadata.
4. Generate short-lived signed URLs for approved private PDFs on the server.
5. Connect saved books, reading history, reviews, and reports to authenticated operations.
6. Protect dashboard and moderation pages using server-validated sessions and role checks.
7. Add rate limiting and abuse protection for public report/contact endpoints.

Do not make a bucket public to get PDFs working. A private bucket plus a server-generated signed URL is the intended design.

## Troubleshooting

- **Missing environment variables:** confirm `.env.local` is in the project root and restart `npm run dev`.
- **Invalid API key or URL:** copy the URL and publishable/anon key from the same Supabase project.
- **Permission denied / empty query result:** check that the schema ran and review the table's RLS policies. Do not fix this by disabling RLS.
- **Profile row missing after test sign-up:** inspect the Auth logs and confirm `on_auth_user_created` exists under Database → Triggers.
- **Email confirmation does not return to the app:** check the Supabase Site URL, allowed redirect URLs, and email delivery configuration.
- **A PDF is publicly accessible:** confirm `book-files` is private. Do not store copyrighted or permission-restricted PDFs in the public covers bucket.
